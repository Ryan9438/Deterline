## 目标 1：字体资产清单

**结论：任务简报的 `fnt_marsneedcunnilingus` 在本数据文件中不存在**（Mac 移植基座的命名不同）。
共 20 个字体 = 10 英文 + 10 日文。对话主力字体是 **fnt_main**（emSize 24）与 **fnt_maintext**（emSize 12），
`fnt_curs` 才是 displayName="Mars Needs Cunnilingus" 的那个菜单字体。

完整清单、glyph 结构样本、页占用表 → 见 **fonts_dump.md**；原始数据 → **fonts_dump.json**（1.9MB，全部 20 字体 × 全部 glyph 字段）。

要点：
- 英文对话字体 fnt_main / fnt_maintext / fnt_plain 各 269 glyphs = 95 ASCII + 173 假名 + 1 DEL（**无任何汉字**）。
- 日文组 fnt_ja_main 等 6 个字体各 780 glyphs = ASCII + 假名 + **488 个日文汉字** + 24 个中文兼容标点（，。「」…※ 等，完整清单 `fnt_ja_main_cjk清单.txt`）。这证明**引擎对 >0xFFFF 以下大码点 glyph 完全支持**，且文件里已有 CJK 位图先例——但字形为日文新字体形，数量（488）远不够简体中文（GB2312 一级 3755 字），缺简体特有字形。
- 每字体恰好一个 `Texture`（UndertaleTexturePageItem）→ 一个 `UndertaleEmbeddedTexture` 页；glyph 的 SourceX/Y 是**页绝对坐标**（GMS1 风格，glyph 无独立 TextureItem——本构建的 Glyph 类型根本没有该字段）。

## 目标 2：对话字体链

**结论：字符→glyph 映射是引擎内置（GMS1.4 draw_text），脚本层无自定义查找；字体切换的咽喉是 `scr_setfont`。**

调用链（全部有反编译证据，存 `decompiled/`）：

```
obj_time.Create_0            global.locale = os_get_language()+"_"+region; global.language = substr(global.locale,1,2)
obj_dialoguer.Create_0       writer = instance_create(..., OBJ_WRITER)          ← 只画对话框矩形，不画字
 └─ obj_base_writer.Create_0 SCR_TEXTTYPE(global.typer)
     └─ gml_Script_SCR_TEXTTYPE（545 行，逐 typer 分支）
        └─ script_execute(SCR_TEXTSETUP, fnt_main, c_white, ...)   ← typer 0 默认 = fnt_main
           （SCR_TEXTSETUP 第 1 行：myfont = argument0;）
     └─ obj_base_writer.Draw_0（615 行，逐字符循环）
        ├─ scr_setfont(myfont)         ← 每个字符调用一次（第 407 行）
        │   └─ if (global.language=="ja") { fnt_main→fnt_ja_main; fnt_maintext→fnt_ja_maintext; fnt_plain→fnt_ja_plain; }
        │      draw_set_font(newfont)                             ← 语言切换的唯一咽喉
        └─ draw_text(...)                                   ← 引擎按 UndertaleFont.Glyphs 查 glyph
```

- 对话默认字体：SCR_TEXTTYPE 各 typer 分支依次是 fnt_main（typer 0）、fnt_plain、fnt_curs、fnt_maintext（NPC 对话）……`fnt_maintext` 在全游戏被 55 处引用、`fnt_main` 27 处（完整映射见 p2_output.log 的 USE 段）。
- **中文漏洞**：`global.language` 来自系统 locale（`os_get_language()`），中文系统上为 `"zh"`；而 `scr_setfont` 只对 `"ja"` 做映射 → zh 直接落到英文字体 → 无 CJK glyph → 对话必然显示空白/豆腐块。这正是 C3b 要解决的路径。
- 假名的存在证明 data 文件的字符串表支持非 ASCII UTF-8 内容（中文文本字符串本身可放，属 C3 文本任务范围）。
- 换行风险（给 C3 实现的预警）：obj_base_writer 的换行按空格断词，中文无空格，长句会溢出对话框——需在文本层预折行或改 writer 逻辑（本侦察只标记，不处理）。

## 目标 3：API 可行性探针（全部内存验证，未落盘游戏数据）

### 3a. 现有字体读取 + Glyph 字段全集 — **通过**（p3a_output.log）
- `Data.Fonts` 可按名检索；`Glyphs` 为 `UndertalePointerList<UndertaleFont.Glyph>`。
- Glyph 全字段：`Character(ushort), SourceX/Y/W/H(ushort), Offset(short), Shift(short), UnknownAlwaysZero(short), Kerning(UndertaleSimpleListShort<GlyphKerning{Character,ShiftModifier}>)`。
- 旧 API 名（TexturePage/GlyphInfo/EmittedSize/DisplayHeight/Shifting/TextureItem）**全部不存在于本构建**——写注入脚本时须用上表名称（fonts_dump.md §3）。

### 3b. TexturePage 体系 — **通过**（p3b_output.log）
- `Data.Textures` 不存在（CS1061 实证）；页列表是 `Data.EmbeddedTextures`（26 页）+ `Data.TexturePageItems`（6550 项）。
- Font.Texture = TexturePageItem，其 `.TexturePage` = UndertaleEmbeddedTexture；反向枚举 TexturePageItems 可得页的占用图。
- **注意坑**：`UndertaleEmbeddedTexture.TextureWidth/Height` 未加载时读数为 0，真实尺寸在 `TextureData.Width/Height`。
- 页占用（8px 网格）：emb#19（英文字体页 1024x1024）67% 占用，最大空闲矩形 **768x384 @ (256,640)**；emb#20（日文页 2048x2048）92%，空闲 **512x632 @ (1536,1416)**；emb#18 49%。
- 抽页验证：`Image.SavePng()` 成功把 emb#19 导出为 1024x1024 PNG（`emb19_font_page_extract.png`，68KB；白区=glyph 位图，黑区=透明空闲区，与占用计算吻合）。

### 3c. 内存构造新字体/新 TPI — **通过**（p3c_output.log）
```
TPI_NEW_OK: index=6550 src=1536,1416 512x512 page=emb#20
FONT_ADD_OK: Data.Fonts.Count=20->21
FONT_READBACK_OK: name=fnt_c3b_probe glyphs=4 emSize=24 range=19968-40959 texture=TPI#6550 firstGlyph=U+4E2D
KERNING_ADD_OK / EXISTING_FONT_APPEND_OK: fnt_ja_main glyphs 780->781
CLEANUP_OK（内存复原，进程退出即弃，无 -o 落盘）
```
- `new UndertaleFont()` 全字段可设，`Data.Fonts.Add` 后按名可查回；`new UndertaleTexturePageItem()` 挂已有页（`tpi.TexturePage = emb`）可行；`Data.Strings.MakeString()` 造名。**没有抛异常、没有隐藏的必填注册步骤**（无 ID 字段，字体索引=列表位置）。

### 3d. EmbeddedTexture / 从 PNG 构造 — **通过**（p3d_output.log）
- `UndertaleEmbeddedTexture.TexData`：`Width/Height/FormatBZ2/FormatQOI` **全部只读**，由赋给 `Image` 的 GMImage 派生（CS0200 两次实证）；Image 为 null 时读 Width 会 NRE。
- **黄金 API：`GMImage.FromPng(byte[])`**（UndertaleModLib.Util.GMImage 静态工厂）——PNG 字节直接进。另有 `FromMagickImage/FromQoi/FromDds`；Magick.NET 在 CLI 宿主中可用。
- 往返实证：emb#19 → `SavePng(ms)` 68163B → `FromPng` → 赋给全新 `TexData.Image` → Width/Height 自动 1024x1024。**即：新页 = FromPng(编辑好的 2048x2048 PNG) + 设 Name + 加入 Data.EmbeddedTextures/Data.TexturePageItems**，与本文件既有页的原生存储格式（ImageFormat=Png）一致。
- 新 TexData 无需 TextureGroupInfo（本文件所有页 TextureInfo=null）。
- 附带发现：现有页的空置区域是"透明黑"，glyph 区是"白色+alpha"——做 C3 合成位图时保持同一直通 alpha 即可（实现期需再做一次像素级校验，见 §5 开放项）。

## 目标 4：容量与方案建议

### 容量数学
- 简体中文需求：GB2312 一级 3755 字（或按翻译语料实际用字 1500-3000）。
- 对话字号：fnt_main emSize=24 → CJK glyph ≈24x24 + 4px 边距 = 28px 栅距；3755 字 × 784px² ≈ 2.94M px² → **√≈1716，一块 2048x2048 页可容纳**（理论 5349 格）。emSize 12 的 maintext/plain 同页还能再放两套小号图集（12px glyph/16px 栅距仅需 0.96M px²）。
- 现有两页的零散空闲（emb#19 768x384 ≈ 376 字 @28px；emb#20 512x632 ≈ 412 字）**都不够**整包中文 → 必须新页（或扩页）。
- 页尺寸上限观测：全文件 26 页，最大 2048x2048（4 处出现）；未观测到 4096。**建议以 2048x2048 为安全上限**（引擎为 GMS1.4 Mac runner，2048 有原生前例，4096 无证据）。

### 方案对比

**方案 A：替换主字体 glyph 表并扩页（fnt_main 加 CJK glyphs + emb#19 扩到 2048）——不推荐**
- 需重排 emb#19 全部 11 个 TPI 与 6 个字体的全部 glyph 页绝对坐标（~1000+ 条坐标改写），且 12x7/2x2 的小 TPI 属于未知精灵。牵一发动全身，任一坐标错 = 花屏，且无回滚参照。风险：高。

**方案 B（推荐）：新建 fnt_cjk 字体 + 新 2048x2048 页 + 改 scr_setfont 切换链**
- 纯增量：新 EmbeddedTexture（FromPng）→ 新 TexturePageItem(s) → 新 UndertaleFont（ASCII+CJK 同图集，保证中英混排）→ Data.Fonts.Add；现有资源零改动。
- 唯一代码改动点 = `scr_setfont`，仿照现有 ja 分支加 zh 映射（fnt_main→fnt_cjk_main 等），模式与 0.9.1.2 已验证的 ja 机制完全同构。
- 字号缺口：emSize 24（main）与 12（maintext/plain）需要两套图集 → 两块新页（或 12 号用 2x 缩放渲染另议）；同页可共存多字体区域。
- 风险：中。① 域F教训：对 scr_setfont 的代码编辑必须做字节码级 before/after 验证 + 游戏内实测（CSX 静态检查不可信）；② Mac 移植存在 `spr_fonts_ja_preload`（2x2 精灵）暗示**新页可能需要预加载精灵**，实现时需验证字体是否自动触发页加载；③ CJK 无空格换行（见目标 2）；④ 每字体仅一页一区域，CJK 字库若超 5349 字需分页分字体。

**方案 C：直接替换主字体纹理页并重排 glyph（整体重打包 emb#19）——不推荐**
- 与 A 同量级的坐标重排工作，外加整页位图重建；收益仅是把 1024² 扩成 2048²，而 B 用增量方式达到同样容量。风险：高，收益无差。

### 给 C3 实现的开放验证项
1. 页位图像素语义（直通 alpha vs 预乘）——合成 CJK 位图前用 1 个测试 glyph 游戏内验证。
2. 新页是否需要 preload 精灵（对照 spr_fonts_ja_preload 的引用链）。
3. scr_setfont 修改的字节码验证协议（域F：反编译一致 ≠ 字节码一致）。
4. 中文折行策略（文本层预折行 vs writer 改造）。
